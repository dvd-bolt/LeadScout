# LeadScout: запуск на другом компьютере

Актуально для версии с Mini App, дизайном Mono и административным разделом, SQLite v7.
Инструкция сверена с кодом 11 сентября 2026 года.

На выбранном компьютере будут работать бот, API, планировщик и браузер hh.ru.
Пользоваться Mini App можно с другого устройства через Telegram. Компьютер с сервером
должен оставаться включённым, без сна и с доступом к интернету.

Если нужно только открыть приложение с другого телефона или ноутбука, переносить сервер
не требуется: откройте того же бота в Telegram под пользователем с выданным доступом.

## 1. Что потребуется

- Современная 64-битная Windows, macOS или Linux. Для Linux проще использовать Ubuntu/Debian.
- Git, Python **3.13.x**, Node.js **24 LTS** с npm, `cloudflared`.
- Доступ к репозиторию и к текущему `.env` либо собственные токены для новой установки.
- Для переноса данных — согласованная копия SQLite и **тот же** `SESSION_ENCRYPTION_KEY`.
- Доступ компьютера к Telegram, Gemini, hh.ru и Cloudflare.

Команды Windows ниже предназначены для **PowerShell**, команды macOS/Linux — для Terminal/bash/zsh.
Запускайте их из папки проекта, если явно не указано иное. Не вводите символы приглашения терминала.

**Один BOT_TOKEN — один запущенный экземпляр LeadScout.** Перед переносом остановите старый
сервер. Два экземпляра могут конфликтовать за Telegram polling и выполнять независимую
автоматизацию. Копии SQLite на двух компьютерах сами не синхронизируются.

## 2. Подготовить перенос со старого компьютера

Этот раздел нужен, чтобы сохранить существующих участников, аккаунты hh.ru, резюме и историю.
Для совершенно новой установки перейдите к разделу 3, затем используйте вариант 6Б.

1. Дождитесь окончания текущих заданий или остановите их через интерфейс. При необходимости
   выключите автопоиск: его настройки хранятся в базе и сохранятся после переноса.
2. Остановите `server_app.py`: нажмите **Ctrl+C** в его терминале и дождитесь завершения.
   Если сервер запущен в фоне, через Docker или как служба, остановите именно этот экземпляр.
3. Остановите старый `cloudflared` через **Ctrl+C** в его терминале.
4. Создайте резервную копию базы штатным скриптом.

macOS/Linux:

```bash
.venv/bin/python backup.py
```

Windows:

```powershell
.\.venv\Scripts\python.exe backup.py
```

Без дополнительных настроек файл появится в `backups/leadscout_ГГГГ-ММ-ДД_ЧЧ-ММ-СС.db`
рядом с базой. Скрипт читает `DB_PATH` и `BACKUP_DIR`, если они заданы, и оставляет последние
14 копий. Переносимую копию сохраните отдельно от каталога ротации.

5. Подготовьте три вещи: **актуальный код**, **текущий `.env` из корня проекта** и **полученную копию базы**.

Не копируйте только `leadscout.db` во время работы сервера: свежие данные могут находиться
в WAL. `backup.py` создаёт согласованный самостоятельный файл, которому для восстановления
не нужны старые `-wal`/`-shm`.

`.env`, база, `.venv`, `web/node_modules` и `web/dist` исключены из Git. Клонирование репозитория
не переносит ключи и данные. `.env` и базу передайте приватно; в репозиторий их добавлять не нужно.

Если переносите код через Git, сначала убедитесь, что нужные изменения сохранены и отправлены
в репозиторий. Незакоммиченные изменения и новые локальные файлы не появятся после `git clone`.
На момент подготовки этой инструкции в рабочей папке были такие изменения, включая админку.
Альтернатива — скопировать текущие исходники, включая новые файлы, отдельным архивом.

Не переносите `.venv` и `web/node_modules` между компьютерами: они устанавливаются заново.
Не используйте рабочую SQLite непосредственно в синхронизируемой папке OneDrive/iCloud/Dropbox.

## 3. Установить инструменты на новом компьютере

### Git и Node.js

Установите [Git для своей ОС](https://git-scm.com/install/) и
[Node.js 24 LTS](https://nodejs.org/en/download). В установщике Node.js оставьте npm.
На Linux на странице Node.js выберите инструкции для Linux и ветку 24.
После установки откройте новое окно терминала:

```text
git --version
node --version
npm --version
```

`node --version` должен показать `v24.…`. Не используйте старый Node.js из случайного системного пакета.

Если PowerShell блокирует `npm.ps1`, используйте **`npm.cmd` вместо `npm`** во всех командах ниже.
Менять общую политику безопасности PowerShell для запуска проекта не требуется.

### Python 3.13 через uv

Чтобы на всех ОС получить одну версию Python, можно установить менеджер `uv`.
Официальные варианты установки: [Astral — установка uv](https://docs.astral.sh/uv/getting-started/installation/).

macOS/Linux:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Windows, PowerShell:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Это команды официального установщика uv; выполнять их достаточно один раз.
После установки откройте новое окно терминала и выполните:

```text
uv --version
uv python install 3.13
```

Если Python 3.13 уже установлен, uv необязателен: ниже приведён вариант создания окружения без него.

### Cloudflare Tunnel

Нужен именно **`cloudflared`**, а не приложение Cloudflare WARP.
Официальные загрузки для всех ОС: [Cloudflare — cloudflared](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/downloads/).

- **macOS:** если установлен Homebrew, выполните `brew install cloudflared`. Иначе используйте
  официальный бинарный файл Darwin под архитектуру своего Mac и добавьте его каталог в PATH.
- **Windows:** установите 64-битный MSI из раздела Windows на странице Cloudflare, затем откройте
  новый PowerShell. Для варианта с отдельным `.exe` используйте его полный путь вместо `cloudflared`.
- **Ubuntu/Debian:** установите официальный `.deb` под свою архитектуру через
  `sudo apt install ./имя_скачанного_пакета.deb` из каталога загрузки либо используйте репозиторий
  пакетов, указанный Cloudflare. На другой Linux-системе выберите соответствующий пакет/бинарный файл.

Проверка:

```text
cloudflared --version
```

## 4. Получить проект и установить Python-зависимости

Клонируйте репозиторий в обычную локальную папку:

```text
git clone https://github.com/dvd-bolt/LeadScout.git
cd LeadScout
```

Для приватного репозитория потребуется вход в GitHub под аккаунтом с доступом.
Если получили архив исходников, распакуйте его и откройте терминал в его корне — рядом
с `server_app.py`, `requirements.txt` и каталогом `web`.

При использовании uv создайте окружение; команда одинакова для всех ОС:

```text
uv venv --python 3.13 --seed .venv
```

`--seed` добавляет pip. [Документация окружений uv](https://docs.astral.sh/uv/pip/environments/).
Если uv не установлен, вместо этой команды используйте `python3.13 -m venv .venv`
на macOS/Linux или `py -3.13 -m venv .venv` на Windows с установленным Python Launcher.
**Выберите один способ создания окружения.**

macOS/Linux:

```bash
.venv/bin/python --version
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m patchright install chromium
```

Windows:

```powershell
.\.venv\Scripts\python.exe --version
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m patchright install chromium
```

Здесь и далее используется полный относительный путь к Python из `.venv`, поэтому активировать
окружение отдельно не нужно. Chromium устанавливается для текущего пользователя ОС;
сервер запускайте под тем же пользователем. [Инструкция Patchright](https://github.com/Kaliiiiiiiiii-Vinyzu/patchright-python).

На Ubuntu/Debian вместо обычной установки Chromium выполните установку с системными библиотеками:

```bash
.venv/bin/python -m patchright install --with-deps chromium
sudo apt install fonts-dejavu-core
```

Установка системных библиотек может запросить пароль sudo. Не запускайте весь бот от root.

## 5. Собрать Mini App

Из корня проекта, одинаково на всех ОС:

```text
npm --prefix web ci
npm --prefix web run build
```

После успешной сборки должен существовать **`web/dist/index.html`**.
`server_app.py` сам раздаёт эту сборку на порту 8000. Отдельный Vite-сервер для обычного
использования не нужен. `npm run dev` предназначен для разработки интерфейса.

## 6. Настроить данные и `.env`

Выберите **6А для переноса** либо **6Б для новой пустой установки**.

### 6А. Перенос текущего LeadScout с сохранением данных

До первого запуска сервера:

1. Скопируйте **текущий `.env`** со старого компьютера в корень нового проекта.
2. Скопируйте резервную базу в корень нового проекта и назовите её **`leadscout.db`**.
   Не перезаписывайте уже используемую базу нового компьютера: сначала сохраните её отдельно.
3. Проверьте, не задан ли в `.env` старый абсолютный `DB_PATH`. Если он есть, удалите эту строку,
   чтобы использовался `leadscout.db` в корне нового проекта, либо укажите новый путь.
   Аналогично проверьте `BACKUP_DIR`.
4. Сохраните исходные токены, **исходный `SESSION_ENCRYPTION_KEY`** и `ROOT_ADMIN_TELEGRAM_ID`.
   Новый Fernet-ключ генерировать нельзя: он не сможет расшифровать перенесённые сессии hh.ru.
5. Пока оставьте прежние `APP_URL` и `WEB_APP_ORIGINS`; замените их на новый адрес в разделе 7
   **до запуска сервера**.

Текущий главный администратор — `1022352992`; первоначальный администратор — `8941766376`.
При переносе фактические роли, отключения и список людей уже находятся в базе. Настройка ROOT
должна совпадать с ROOT этой базы. Смена компьютера не является передачей главной роли.

### 6Б. Новая пустая установка

Этот вариант создаёт новую базу без прежних аккаунтов, истории и участников.

macOS/Linux:

```bash
cp .env.example .env
.venv/bin/python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Windows:

```powershell
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Скопируйте выведенный ключ в `.env` и сохраните его. Не выполняйте копирование шаблона поверх
уже настроенного `.env`. На Windows проверьте, что файл не называется `.env.txt`.

Обязательные настройки в `.env`:

```dotenv
BOT_TOKEN=ВСТАВЬТЕ_ТОКЕН_БОТА
GEMINI_API_KEY=ВСТАВЬТЕ_КЛЮЧ_GEMINI
GEMINI_MODEL=gemini-3.5-flash-lite
SESSION_ENCRYPTION_KEY=ВСТАВЬТЕ_СГЕНЕРИРОВАННЫЙ_FERNET_КЛЮЧ

ROOT_ADMIN_TELEGRAM_ID=1022352992
OWNER_TELEGRAM_IDS=1022352992,8941766376

APP_URL=https://ЗАМЕНИТЕ_АДРЕСОМ_ТУННЕЛЯ
WEB_APP_ORIGINS=https://ЗАМЕНИТЕ_АДРЕСОМ_ТУННЕЛЯ
WEB_SECURE_COOKIES=true

BROWSER_HEADLESS=true
MAX_CONCURRENT_BROWSERS=2
```

Значения с `ВСТАВЬТЕ` и `ЗАМЕНИТЕ` — пояснения, они не должны остаться в готовом файле.
Сохраните остальные ограничения из `.env.example`.

- `BOT_TOKEN`: для существующего бота возьмите текущий токен. Для независимой тестовой установки
  используйте отдельного бота, созданного через [BotFather](https://t.me/BotFather).
- `GEMINI_API_KEY` и `GEMINI_MODEL`: при переносе используйте рабочие значения из текущего `.env`.
  Название в шаблоне — настройка проекта, доступность модели определяется вашим Gemini-аккаунтом.
- `ROOT_ADMIN_TELEGRAM_ID`: главный администратор. Для другого самостоятельного проекта
  укажите его настоящий числовой Telegram ID **до первой инициализации**.
- `OWNER_TELEGRAM_IDS`: только первоначальные администраторы. После создания базы доступом
  управляйте через Mini App. Изменение списка в `.env` не восстанавливает отключённые роли.
- `DOMAIN`: нужен сценарию Docker/Caddy с собственным доменом. Для описанного здесь запуска
  `server_app.py` и Quick Tunnel эта переменная не используется.

На macOS/Linux ограничьте доступ к файлу:

```bash
chmod 600 .env
```

Не помещайте токены в команды Git, URL репозитория, общие скриншоты или публичные документы.

## 7. Запуск: три окна терминала

### Окно 1 — HTTPS-туннель

```text
cloudflared tunnel --url http://127.0.0.1:8000 --protocol http2 --no-autoupdate
```

Скопируйте появившийся адрес вида `https://случайное-имя.trycloudflare.com`.
Окно оставьте открытым. Пока сервер не запущен, запрос через туннель может возвращать 502.

В `.env` замените **обе** строки на полученный адрес без завершающего `/`, без `/#/admin`
и других путей:

```dotenv
APP_URL=https://ваш-новый-адрес.trycloudflare.com
WEB_APP_ORIGINS=https://ваш-новый-адрес.trycloudflare.com
```

Quick Tunnel выдаёт случайный временный адрес; после нового запуска нельзя рассчитывать
на прежнюю ссылку. Аккаунт Cloudflare и собственный домен для этого варианта не нужны.
Это режим для временного доступа, без гарантии постоянной доступности.
[Документация Quick Tunnels](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/).

### Окно 2 — бот, API и планировщик

Откройте терминал **в корне того же проекта**.

macOS/Linux:

```bash
.venv/bin/python server_app.py
```

Windows:

```powershell
.\.venv\Scripts\python.exe server_app.py
```

Это один процесс со всеми компонентами. Не запускайте рядом второй `server_app.py`,
отдельный polling-процесс или несколько Uvicorn workers.

На старте выполняются миграции и восстановление прерванных операций. База создаётся
автоматически, если её нет. Перенесённые анкеты с незавершённой отправкой требуют проверки,
они не отправляются повторно автоматически. Включённый ранее автопоиск сохраняет настройку.

Дождитесь сообщения Uvicorn о работе на `http://0.0.0.0:8000`.
Перед HTTP-сервером выполняется проверка конфигурации и доступности модели ИИ, поэтому запуск
не обязательно мгновенный. Все сообщения остаются в этом терминале.

На этом этапе окно 1 и окно 2 должны оставаться открытыми.

### Окно 3 — проверка и обновление меню Telegram

Локальная проверка на macOS/Linux:

```bash
curl --fail http://127.0.0.1:8000/healthz
```

На Windows:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/healthz
```

Ответ: `{"status":"ok"}`; PowerShell может показать его как таблицу `status / ok`.
Аналогично проверьте **ваш новый** публичный адрес:

```text
https://ваш-новый-адрес.trycloudflare.com/healthz
```

Его можно открыть обычным браузером. Успешный `/healthz` подтверждает ответ HTTP-процесса;
он сам по себе не проверяет вход в hh.ru, ИИ и полный сценарий Telegram.

Когда публичный адрес отвечает, обновите кнопку Mini App. Из корня проекта:

macOS/Linux:

```bash
.venv/bin/python -m scripts.set_mini_app_menu
```

Windows:

```powershell
.\.venv\Scripts\python.exe -m scripts.set_mini_app_menu
```

Скрипт меняет глобальную кнопку меню и кнопки начальных администраторов, затем читает настройки
обратно. Он не запускает второй polling и не отправляет сообщения. Нормальный результат —
`Default Mini App menu verified`; при отсутствии личного чата предложит сначала нажать Start.

Этот шаг **меняет адрес меню самого Telegram-бота для пользователей**, поэтому старый экземпляр
с тем же токеном к этому моменту должен быть остановлен.

Если отдельно настроена кнопка **Launch app / Main Mini App** в профиле бота через BotFather,
обновите и её URL в настройках соответствующего бота. Скрипт обновляет Menu Button, а не все
возможные настройки профиля. Старые сообщения с inline-кнопками также сохраняют старую ссылку.

## 8. Проверка в Telegram

1. Откройте своего бота; для текущего проекта — [@leadscout_robot](https://t.me/leadscout_robot).
2. Отправьте `/start` или нажмите «Начать», чтобы получить новую кнопку с актуальным адресом.
3. Закройте старое окно Mini App и нажмите «Открыть LeadScout» заново.
4. Под `1022352992` откройте **Настройки → Администрирование**: должна быть вкладка «Люди».
5. Под `8941766376` доступны обзор, задания и журнал; управления людьми нет.
6. При переносе проверьте наличие своих аккаунтов, резюме и истории. Если hh.ru больше
   не принимает сохранённую сессию, выполните повторный вход в соответствующий аккаунт.

У новой базы действуют начальные назначения; у перенесённой — фактические роли из неё.
Другие люди получают доступ после добавления главным администратором во вкладке «Люди».
Неизвестному или отключённому ID кабинет недоступен.

**Прямое открытие главной страницы в обычном браузере не заменяет вход из Telegram.**
Сообщение «Откройте LeadScout из Telegram» без подписанных данных Mini App ожидаемо.
Не отключайте авторизацию, CSRF или Secure cookies для обхода этой проверки.

## 9. Повторный запуск: короткая памятка

Когда зависимости и сборка уже установлены:

1. Убедитесь, что прежний сервер с этим BOT_TOKEN остановлен.
2. Запустите туннель в первом окне:
   `cloudflared tunnel --url http://127.0.0.1:8000 --protocol http2 --no-autoupdate`.
3. Запишите выданный HTTPS-адрес в `APP_URL` и `WEB_APP_ORIGINS`, сохраните `.env`.
4. Во втором окне запустите `server_app.py` своим Python из `.venv`.
5. Проверьте локальный и публичный `/healthz`.
6. В третьем окне выполните своим Python `-m scripts.set_mini_app_menu`.
7. Переоткройте Mini App через свежую кнопку бота.

После изменения `.env` уже работающий сервер нужно перезапустить: файл не перечитывается
автоматически. Если изменился только код интерфейса, перед запуском выполните сборку заново.

Остановка: сначала **Ctrl+C в окне сервера**, дождитесь завершения, затем **Ctrl+C в окне туннеля**.
База останется на диске. При завершении заданий учитывайте, что уже выполненное действие на hh.ru
нельзя отменить остановкой локального процесса.

## 10. Обновления, резервные копии и постоянная ссылка

Перед обновлением остановите работу, сохраните базу через `backup.py` и текущий `.env`.
Получите актуальные исходники; если папка клонирована и нет собственных незавершённых изменений,
используйте `git pull --ff-only`. Конфликт не обходите удалением файлов или `reset --hard`.

Повторите установку `requirements.txt`, установку Chromium и сборку `npm ci` / `npm run build`.
Затем выполните обычный запуск. Не запускайте старый backend со схемой v6 на базе v7.
Возврат на такую старую версию требует соответствующей резервной базы; новые данные перед откатом
сохраняются отдельно.

Для постоянной HTTPS-ссылки вместо Quick Tunnel нужен постоянный Cloudflare Tunnel с доменом
или сервер с HTTPS. Локальный компьютер при этом всё равно должен работать. Для доступности
без включённого личного компьютера нужен VPS/другой постоянно включённый сервер.
[Постоянный Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/get-started/create-remote-tunnel/).

Штатный `docker-compose.yml` в этом репозитории — отдельный сценарий VPS с Caddy и доменом:
он не публикует порт приложения 8000 на localhost хоста. Команды Quick Tunnel из этой инструкции
предназначены для непосредственного запуска `server_app.py`, без этого Compose.

## 11. Если не запускается

| Симптом | Что проверить |
|---|---|
| `git`, `uv`, `node`, `npm` или `cloudflared` не найден | Установку и PATH; откройте новое окно терминала. Для отдельного `cloudflared.exe` используйте полный путь. |
| PowerShell запрещает `npm.ps1` | Замените `npm` на `npm.cmd`. Python запускается напрямую из `.venv`, активация не нужна. |
| `No module named …` | Команда должна использовать Python из `.venv`; установите зависимости из `requirements.txt`. |
| Не найден Chromium / `Executable doesn't exist` | Выполните своим Python `-m patchright install chromium` под тем пользователем ОС, который запускает сервер. На Linux используйте `--with-deps`. |
| `ZoneInfoNotFoundError` | Установите пакет: своим Python выполните `-m pip install tzdata`. Особенно актуально для минимальных ОС. |
| `Missing required environment variables` | `.env` лежит рядом с `server_app.py`, имеет правильное имя и заполненные обязательные значения. |
| `ROOT_ADMIN_TELEGRAM_ID is required` / `ROOT_MISMATCH` | Укажите ROOT. Для перенесённой базы он должен совпадать с уже назначенным главным администратором. Не удаляйте базу, чтобы обойти проверку. |
| Не расшифровываются сессии | Верните исходный Fernet-ключ, соответствующий этой базе. Повторная генерация не восстанавливает старые сессии. |
| Ошибка миграции с ID совпадающих аккаунтов | Сохраните копию и разберите указанные дубликаты. Не объединяйте и не удаляйте записи наугад. |
| `address already in use`, порт 8000 занят | Найдите и корректно остановите прежний сервер. В штатном runner порт 8000 фиксирован; произвольная переменная `PORT` его не меняет. |
| Telegram `Conflict` / другой `getUpdates` | Этот токен уже используется другим polling-процессом. Остановите старый экземпляр, включая старый компьютер/контейнер. |
| Telegram сообщает об активном webhook | Для polling существующий webhook должен быть снят осознанно. Не удаляйте его у другого работающего сервиса; используйте отдельного бота или перенесите обслуживание полностью. |
| Локальный `/healthz` не отвечает | Сначала смотрите окно `server_app.py`: пока локальный API не работает, туннель проблему не исправит. |
| 502 / ошибка туннеля | Сервер должен отвечать на `127.0.0.1:8000`, а `cloudflared` — продолжать работать на том же компьютере. Проверяйте актуальный адрес. |
| Quick Tunnel не создаётся | Проверьте сеть и сообщение cloudflared. Существующий `config.yaml` в пользовательской `.cloudflared` может мешать Quick Tunnel; сохраните его и временно переименуйте, если он не нужен другому туннелю. |
| Кнопка ведёт на старый адрес | Обновите обе переменные URL, перезапустите сервер, выполните `scripts.set_mini_app_menu`, получите свежий `/start`. Проверьте отдельно Main Mini App в BotFather. |
| Mini App пустой / 404 | Проверьте наличие `web/dist/index.html` и успешную production-сборку. |
| 403 при сохранении | `WEB_APP_ORIGINS` должен точно совпадать с текущим HTTPS-origin. Переоткройте приложение для получения новой сессии. Не выключайте CSRF. |
| «Доступ закрыт» / «Недостаточно прав» | Проверьте Telegram ID, роль и статус в административном разделе. Изменение OWNER-списка после первого запуска не выдаёт права. |
| Gemini 401/403/429 или модель не найдена | Проверьте ключ, доступность выбранной модели, квоту и сеть. Ошибка ИИ не означает, что настройки Telegram неверны. |
| После сна ноутбука приложение недоступно | Разбудите компьютер, проверьте сервер/туннель. При новом адресе повторите обновление `.env` и меню. |

Не используйте отключение проверки TLS как способ исправить сетевые ошибки.

## 12. Дополнительная проверка установки

После сборки UI можно запустить тесты из корня проекта.

macOS/Linux:

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
.venv/bin/python -m ruff check .
.venv/bin/python -m pip check
```

Windows:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m pip check
```

Тесты используют временные базы и подменяют внешние отправки. Если `web/dist` отсутствует,
браузерные тесты могут пропускаться: сначала выполните раздел 5.

На текущем Mac заключительный прогон дал **227 passed**. Это не выдаётся за проверку на всех ОС:
чистая установка Windows/Linux по этому документу в данной сессии не выполнялась.
[Отчёт проверки приложения](docs/refactor/ADMIN_RECHECK_2026-09-11.md).

Отдельно проверьте PDF-экспорт на целевой ОС. Текущий модуль отчётов ищет Arial в Windows
и DejaVu/Liberation в стандартных Linux-каталогах; на macOS эти пути обычно отсутствуют,
и кириллица PDF требует отдельной настройки поиска шрифта в модуле отчётов.
Это ограничение PDF-экспорта, не установки бота или Mini App.

Доступ к живым hh.ru/Gemini и открытие Mini App в Telegram на устройстве подтверждаются
отдельным ручным проходом после успешного локального запуска.

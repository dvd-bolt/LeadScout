# LeadScout — итог ревью и исправлений

Дата перепроверки: **17 сентября 2026**. Все **45 из 45** найденных продуктовых, UI и технических проблем закрыты. `[x]` означает, что исходный критерий реализован и проверен локальным тестом либо проверкой соответствующего пути кода.

## P1 — безопасность внешних действий и сохранность данных

- [x] **LS-01. Восстанавливать незавершённые попытки отклика после аварийного завершения процесса.** Попытки, прерванные во время отправки или подтверждения, восстанавливаются как требующие ручной сверки, получают видимое событие и блокируют повторную отправку. Доотправочные стадии остаются повторяемыми.
- [x] **LS-02. Сверять анкеты по точному ID вакансии.** ID вакансии нормализуется и хранится отдельно; ручное решение обновляет только точное совпадение, включая случай `123`/`1234`.
- [x] **LS-03. Не создавать новую публикацию после частично созданного резюме.** Незавершённая попытка и любой сохранённый внешний ID переиспользуются независимо от нового ключа запроса.
- [x] **LS-04. Не публиковать резюме, если выбранная видимость не установлена.** Интеграция требует подтверждённое состояние контрола до клика и повторно сверяет фактическую видимость в созданном резюме.
- [x] **LS-05. Гарантировать выбранное резюме до потенциально мгновенного отклика.** Первый потенциально отправляющий клик разрешён только при точном доказательстве ID резюме в атрибутах кнопки; совпадения по подстроке и отсутствие ID блокируются.
- [x] **LS-06. Проверять, что вопросы hh.ru не изменились между подготовкой и отправкой анкеты.** Сохраняется отпечаток схемы вопросов; изменение порядка, типа, обязательности или вариантов требует нового подтверждения.
- [x] **LS-07. Привязать подтверждение изменений профиля к версии и проверять его на всех серверных путях.** Первичная публикация и продолжение проверяют ревизию, целевой аккаунт и актуальный fingerprint конфликтов; UI сбрасывает подтверждение после изменений.
- [x] **LS-08. Останавливать все операции аккаунта до удаления его данных.** Удаление устанавливает барьер под тем же admission-lock, останавливает coordinator и TaskRegistry и только затем удаляет записи; новая и уже допускаемая работа не может пройти между отменой и удалением.

## P2 — продукт, формы и интерфейс

- [x] **LS-09. Не нормализовать списки на каждом нажатии клавиши.** Сырой ввод списков и навыков живёт до `blur`, сохраняется в `localStorage` и восстанавливается после перезагрузки.
- [x] **LS-10. Сохранять последние изменения перед закрытием мастера и сменой раздела.** Закрытие и переход вперёд ожидают сохранения; каждый ввод одновременно резервируется локально, поэтому сетевой сбой или размонтирование не теряет правки.
- [x] **LS-11. Сохранять полные данные курсов, сертификатов, экзаменов и рекомендаций.** Редактор меняет имя, организацию, год и описание существующей записи без пересоздания и потери полей.
- [x] **LS-12. Исправить классификацию успешного preflight.** `READY` включён в общий контракт успешных результатов и одинаково трактуется операцией, административной задачей и UI.
- [x] **LS-13. Реально применять подтверждённые изменения уже заполненных полей профиля.** После подтверждённого preflight имя, город, дата рождения и контакты заменяются, а не заполняются только при пустом поле.
- [x] **LS-14. Проверять все переносимые значения перед статусом «перенос подтверждён».** Итоговая сверка включает даты опыта, текущую работу, уровни образования, навыков и языков, валюту, условия, подробности дополнительных разделов, транспорт, ссылки, видимость, профиль и контакты.
- [x] **LS-15. Усилить валидацию черновика до запуска браузера.** Проверяются диапазоны и порядок дат, email, телефон, URL, зарплата и согласованность зависимых полей с адресными ошибками мастера.
- [x] **LS-16. Заменить ручной ввод справочных значений hh.ru выбором из допустимых вариантов.** Пол, валюта, уровень образования/языка, занятость и графики представлены контролируемыми вариантами; неоднозначные профессия и город возвращают варианты с ID, а выбранный ID используется интеграцией.
- [x] **LS-17. Восстанавливать состояние длительных операций при повторном открытии экрана.** Операции имеют `account_id` и `resource`; синхронизация, аудит, PDF, публикация и matching восстанавливают активный ID, polling и последний результат после повторного открытия.
- [x] **LS-18. Восстанавливать черновики, зависшие в `PARSING`.** Startup recovery переводит их в `NEEDS_INPUT` с действием повторной загрузки PDF; список опрашивается, пока разбор активен.
- [x] **LS-19. Добавить восстановление после конфликта автосохранения.** Мастер хранит локальную копию, блокирует дальнейшую навигацию и предлагает явно загрузить серверную либо сохранить локальную версию поверх актуальной ревизии.
- [x] **LS-20. Проверять ревизию не только при подтверждении, но и при редактировании анкеты.** `PATCH` атомарно сравнивает `expected_revision`; UI показывает серверное и локальное письмо/ответы и не продолжает отправку до явного выбора.
- [x] **LS-21. Поддержать select и множественный выбор в анкетах.** Модель, parser, редактор и заполнение поддерживают `select` и массив значений checkbox; неизвестный тип всегда переводится в ручное подтверждение.
- [x] **LS-22. Сделать «Пропустить» устойчивым решением для вакансии.** `SKIPPED` участвует в проверке открытого решения и сохраняется как минимальный tombstone после очистки истории.
- [x] **LS-23. Не выдавать недоступность ИИ за нерелевантную вакансию.** `AIServiceError` даёт `ERROR_AI`, безопасную причину, признак повторяемости и действие восстановления; отрицательное решение ИИ остаётся отдельным `SKIPPED_IRRELEVANT`.
- [x] **LS-24. Не помечать цикл поиска успешным при сбое загрузки выдачи.** Ошибки навигации, parser и истёкшая сессия попадают в `search_errors`; пустая выдача при ошибке завершает цикл как `ERROR`, а частичная — как предупреждение, и результат сохраняется отдельно.
- [x] **LS-25. Добавить пагинацию истории и отдельный доступ ко всем неопределённым откликам.** История использует cursor pagination, анкеты загружаются всеми страницами, а `review_required` возвращается отдельным полным списком без произвольного лимита.
- [x] **LS-26. Обновлять историю откликов во время работающего поиска.** История опрашивается во время видимой вкладки, обновляется при focus и имеет ручную дозагрузку страниц.
- [x] **LS-27. Добавить прямой переход к вакансии из анкеты и события сверки.** Карточки содержат ссылку hh.ru, полную дату, точную попытку, отправленное письмо и название/ID использованного резюме.
- [x] **LS-28. Согласовать дату ручной сверки с дневными счётчиками.** Фактической датой остаётся дата попытки; старая сверка не расходует сегодняшний лимит, а статистика строится по той же дате события.
- [x] **LS-29. Включить CSRF/Origin-проверку для ручной сверки отклика.** Endpoint решения использует `require_csrf`; отсутствие или неверность Origin/token не меняет данные.
- [x] **LS-30. Сохранять и восстанавливать шаг входа в hh.ru.** `/login-flows/active` возвращает серверный шаг, account ID, CAPTCHA и оставшееся время; UI восстанавливает форму, опрашивает активный flow и удаляет устаревшее локальное состояние при `NONE`.
- [x] **LS-31. Применять `snapshot_id` из ссылки на аудит.** Выбранный snapshot передаётся в запрос аудита и явно показан перед запуском.
- [x] **LS-32. Объяснить, что «Запустить поиск» включает регулярные автоматические отклики.** UI показывает периодичность, аккаунт, выбранное резюме, лимит и факт автоматической отправки подходящих откликов.
- [x] **LS-33. Согласовать переключатель сопроводительного письма с фактической отправкой.** При выключении необязательное предзаполненное поле очищается; обязательное поле останавливает автоотправку вместо скрытой точки.
- [x] **LS-34. Показывать конкретные причины отказа массового запуска.** Массовый запуск возвращает код и безопасное сообщение для каждого аккаунта и не блокирует остальные готовые аккаунты.
- [x] **LS-35. Дать доступ к независимым аудитам после подключения/удаления аккаунта.** Есть фильтры «Все», текущий аккаунт и независимые; сохранённое имя источника остаётся после `ON DELETE SET NULL`, история загружается всеми страницами.
- [x] **LS-36. Не обрезать резюме и вакансию без предупреждения при ИИ-анализе.** Скрытые срезы входов удалены; PDF сверх лимита выдаёт явную ошибку вместо молчаливого усечения.
- [x] **LS-37. Ограничить повторные ИИ-задания и параллелизм.** Аудит и matching дедуплицируются по resource, UI отслеживает активные операции до терминала, сервер допускает не более одной ИИ-задачи и трёх длительных задач на пользователя.

## P3 — сопровождение и эксплуатация

- [x] **LS-38. Повысить читаемость вторичных подписей в зелёной теме.** Muted-текст затемнён до контраста не ниже 5:1 на основных поверхностях; disabled оформлен отдельно.
- [x] **LS-39. Локализовать технические статусы и ключи оценок.** Общий словарь переводит статусы, этапы и категории аудита и связывает состояния внимания с доступным действием.
- [x] **LS-40. Привести документацию к актуальному мастеру и версии БД.** README описывает текущий draft → preflight → publish/reconcile, SQLite v12, retention, экспорт, health и резервные копии.
- [x] **LS-41. Исправить Ruff и включить проверки в CI.** GitHub Actions устанавливает Chromium, собирает UI до pytest и запускает Ruff, полный pytest и `pip check`; приёмочные дефекты больше не скрыты `xfail`.
- [x] **LS-42. Согласовать контракты состояний между API, jobs и UI.** Общий backend-контракт `OperationResultStatus` и единственная функция disposition используются OperationManager и TaskRegistry; соответствующий union есть в TypeScript. Поля мастера вынесены в отдельный компонент, административная страница разбита на обозримые блоки.
- [x] **LS-43. Освобождать браузерные процессы для неиспользуемых прокси.** Пул ведёт время последнего использования и закрывает простаивающие engines через планировщик, сохраняя активные контексты.
- [x] **LS-44. Задать сроки хранения и доступный экспорт/удаление пользовательской истории.** События, попытки и search runs хранятся 180 дней, операции 30, аудиты 365; старые подтверждённые отклики и пропуски обезличиваются до ID-tombstone, неопределённые отправки сохраняются. UI поддерживает JSON-экспорт и удаление подробной истории.
- [x] **LS-45. Сделать проверки здоровья и резервного копирования содержательными.** `/livez` отделён от readiness; `/healthz` проверяет версию/таблицы БД, работающий scheduler и неприостановленные обязательные jobs. Backup использует SQLite backup API, проверяет целостность, отмечает время последнего успеха, имеет healthcheck по возрасту и проверку восстановления.

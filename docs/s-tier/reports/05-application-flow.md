# Модуль 05 — сквозная надёжность отклика

Status: VERIFIED_LOCAL. Live-проверка: NOT_RUN.

## Закрытые причины

- Ошибка до внешней отправки не создаёт вечную блокировку и допускает повтор.
- Timeout, browser error или остановка после этапа SUBMITTING/CONFIRMING,
  а также неподтверждённая отправка и ошибка локальной записи получают
  NEEDS_REVIEW. Успех и дневной счётчик при этом не создаются.
- Открытая анкета и неразрешённая попытка подавляют новый browser-flow
  той же вакансии, не полагаясь на unique index как на exactly-once.
- В истории пользователь фиксирует результат сверки: «есть на hh.ru» или
  «нет на hh.ru». Attempt, event, анкета, hh_applies и счётчик обновляются
  атомарно и идемпотентно; чужой attempt недоступен.
- NEEDS_REVIEW показывает сохранённые письмо и ответы, позволяет сохранить
  или пропустить, но скрывает повторное подтверждение до сверки.
- Подтверждённый hh.ru результат с ошибкой локальной записи получает публичное
  событие ERROR_LOCAL_PERSISTENCE, через которое доступна ручная сверка.
- Gemini сохраняет один ключ; timeout/connection/429/5xx получают максимум
  три попытки. 401/403, невалидная схема и cancel не повторяются.
- Длинный browser input отправляется последовательными блоками с проверкой
  фокуса, поэтому полный тест больше не зависает на тысячах RPC.

## Доказательства

- Сквозные тесты используют реальный coordinator, сервисы, временную SQLite
  и Patchright-формы; подменены только hh.ru, Gemini и Telegram.
- Проверены обычный отклик, анкета, отказ ИИ, duplicate, limit, cancel,
  restart, неизвестный результат и оба варианта ручной сверки.
- Frontend production build через pnpm, TypeScript и Vite выполнен успешно.
- Ruff по всему проекту, compileall и pip check выполнены успешно.
- Полный pytest без исключений: 276 passed за 332.62 секунды.

## Живой этап

Внешние действия не разрешены. Для live smoke test нужны отдельное явное
разрешение на один аккаунт, одно резюме, одну URL вакансии и максимум одну

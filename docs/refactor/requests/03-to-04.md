# Запросы модуля 03 к модулю 04

Frontend готов к согласованному контракту. На момент последней read-only проверки `web_api.py` ещё не экспонировал всю новую поверхность (параллельная backend-работа продолжается). Для интеграции нужны:

- `GET /api/v1/questionnaires/{apply_id}` и `POST /api/v1/questionnaires/{apply_id}/skip` с ownership/404 и idempotent `SKIPPED`; `409` для отправляемой/отправленной анкеты.
- `POST /api/v1/automation/start-all` → `202 {"results":[{"account_id":1,"status":"STARTED"}]}`; включать строку для каждого доступного аккаунта и сохранять неизвестные/новые причины как строковый `status` (опционально `message`).
- `POST /api/v1/login-flows/captcha/language` в том же response shape, что reload.
- `POST /api/v1/audits/{audit_id}/match`: строгий exactly-one-of для `vacancy_text` и `vacancy_url`; URL должен загружаться/нормализоваться только backend-ом.
- `GET /api/v1/operations/{operation_id}`: top-level terminal `status=NEEDS_INPUT`, а `result` содержит `status=NEEDS_FIELDS`, `missing_fields`, полную сохранённую `structured`, `message`.
- `POST /api/v1/accounts/{account_id}/resumes/import`: при продолжении принимать тот же multipart `file` плюс `structured_json`; это новая операция, не продолжение старого operation id.
- `POST /api/v1/audits` и `/audits/pdf`: принимать отсутствие `account_id`, если аудит создаётся из отдельного текста/PDF.

Direct-link формат, который должны генерировать бот/уведомления, подробно зафиксирован в `docs/refactor/module-03.md`. Канонически параметры стоят до `#/`, например:

```text
https://<mini-app-host>/?target=questionnaire&apply_id=123&account_id=7#/
https://<mini-app-host>/?target=resume&account_id=7&snapshot_id=55#/
https://<mini-app-host>/?target=audit&account_id=7&snapshot_id=55#/
```

Просьба при интеграции прогнать существующий `tests/test_mini_app_browser.py` против настоящего FastAPI и отдельно проверить новые direct links. Мои `tests/parallel_ui/**` используют только контрактные browser mocks и не заменяют интеграционный suite.

# Module 02 handoff notes for module 04 (API/bot/integration)

Protocol: parallel-v1

Build the shared business graph with:

```python
build_services(
    db=database,
    coordinator=worker.task_coordinator,
    login_manager=HHLoginManager,
    resume_manager=HHResumeManager,
)
```

All group methods are asynchronous. Convert `ServiceError.code` to the API
transport status in module 04; services never import FastAPI. The supported
codes are `NOT_FOUND`, `CONFLICT`, `INVALID_INPUT`, and `LIMIT_REACHED`.

Important result adapters:

- keep resume import `NEEDS_FIELDS` in the service and translate it to the
  operation-layer `NEEDS_INPUT` response;
- `questionnaires.edit` and `questionnaires.skip` return the storage row with
  JSON fields still encoded;
- `audits.prepare` must happen before scheduling the long-running
  `audits.run`, so it freezes the selected document;
- `audits.run` returns `SUCCESS` or `ERROR` as a business result and never
  persists an AI failure as a zero-score audit;
- audit matching accepts exactly one of `vacancy_text` and `vacancy_url`.

Legacy `worker`, `ai_handler`, and `parsers` imports remain compatibility
facades and can be migrated independently.

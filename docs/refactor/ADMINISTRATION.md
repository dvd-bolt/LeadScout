# Администрирование LeadScout

## Роли и управление

Раздел находится в Mini App: **Настройки → Администрирование**, адрес `#/admin`.
Нижнее меню сохраняет четыре пункта; внутри админки активны «Настройки».

| Роль | Возможности |
|---|---|
| USER | Только собственные аккаунты, резюме, отклики и задания |
| ADMIN | Собственный кабинет, обзор системы, технические задания/ошибки, административный журнал; остановка всех, кроме ROOT |
| ROOT | Возможности ADMIN, управление людьми и остановка любой работы, включая собственную |

ROOT существует в единственном экземпляре. Его нельзя отключить, понизить или заменить через HTTP API.
Передача главной роли требует отдельной серверной процедуры и в эту версию не входит.
Администраторы не получают содержимое чужих резюме, анкет, результатов ИИ, cookies и CAPTCHA.

### Добавление и смена роли

Вкладка «Люди» доступна ROOT. Нужны числовой Telegram ID, роль USER/ADMIN и, при желании,
внутренняя подпись до 100 символов. ID передаётся десятичной строкой и проверяется на диапазон
1…9223372036854775807. Username, телефон и ссылка на профиль не заменяют ID.
Запись можно создать до первого входа. Это выдача доступа, а не проверка существования аккаунта Telegram.
Имя, username и дата последнего входа сохраняются после действительного подписанного входа Mini App.
Приглашение не отправляется: интерфейс предлагает скопировать ссылку на бота.

Повторное добавление возвращает конфликт, а не создаёт дубликат и не восстанавливает отключённую запись.
Изменения требуют `expected_revision`: конфликт 409 обновляет карточку и требует нового решения.
Снятие ADMIN оставляет обычный кабинет. Изменение роли отзывает текущие сессии.

### Отключение и восстановление

«Отключить доступ» транзакционно записывает BLOCKED, увеличивает `auth_version` и `revision`,
выключает автопоиск и сохраняет долговечную команду остановки. Затем отдельная управляющая задача
отменяет задания и закрывает ресурсы. Доступ уже закрыт, даже если закрытие браузера пока не завершилось.
Незавершённый вход закрывается с сохранением строки аккаунта и истории.

Журнал показывает результат каждой цели. При таймауте или ошибке команда остаётся в `NEEDS_CLEANUP`;
кнопка повторной остановки повторяет только незавершённые цели. Восстановление до успешного завершения
остановки запрещено сервером. После восстановления сохраняются прежняя роль и данные, но нужна новая
сессия. Старые cookie не оживают, задания и автопоиск сами не запускаются.

## Остановка заданий

Технический реестр учитывает поиск, анкеты, операции резюме, аудит/сравнение и вход с ожиданием кода.
Он хранит UUID, владельца, аккаунт при наличии, ссылку на операцию, время, состояние и безопасный код.
История поисков начинается после обновления; вымышленные старые задания не создаются.

Остановка поиска выключает автоматизацию его аккаунта. Остановка отдельного аудита или анкеты
не отменяет независимую работу этого владельца. На время незавершённой остановки поиска повторный
запуск этого аккаунта закрыт; после завершения новый ручной запуск разрешён.
Во время остановки входа нельзя начать его заново или отправить следующий OTP/CAPTCHA;
независимые задания пользователя остаются доступны. Отмена самой очистки считается ошибкой,
сохраняет ресурсы для повторной попытки и не выдаётся за успешную остановку.
Массовая остановка выключает автопоиск всех разрешённых для инициатора аккаунтов, включая простаивающие.
Для ADMIN сервер исключает ROOT. Количество заданий, владельцев заданий и аккаунтов с автопоиском
показывается до подтверждения; окончательный состав целей фиксируется при принятии команды.

Ожидание остановки задания ограничено 15 секундами. Неотменяемое внешнее действие не считается
отменённым только потому, что отменена корутина. Неподтверждённая отправка анкеты возвращается в
`NEEDS_REVIEW`; повторная отправка возможна только по новому решению пользователя.
Общий AI-клиент и браузерный движок при адресной остановке не закрываются: закрываются принадлежащие
заданию контексты. Неосвобождённые ресурсы сохраняют ссылки для повторного завершения.

## Конфигурация и миграция

```env
ROOT_ADMIN_TELEGRAM_ID=123456789
OWNER_TELEGRAM_IDS=123456789,987654321
```

Первый ID здесь пример. Рабочие ID задаются только окружением, не исходным кодом.
Миграция v6 → v7 транзакционно создаёт четыре административные таблицы. До изменений делайте
согласованную копию через SQLite backup API; копирование одного `.db` при активном WAL недостаточно.

Bootstrap выполняется при первой инициализации модели доступа. ROOT берётся из отдельной настройки;
остальные начальные владельцы получают ADMIN. Обычные старые строки `users` не означают выданного доступа.
Повторный запуск не переустанавливает роли и статусы из окружения. Несовпадение настроенного ROOT
с базой останавливает запуск, не передавая права. Пустая настройка ROOT также запрещает запуск.

Порядок запуска: миграции → bootstrap → восстановление операций/анкет → технические задания INTERRUPTED
→ восстановление административных остановок → проверка выключенного автопоиска заблокированных людей
→ запуск бота, API и scheduler. Автоматических повторных отправок и перезапусков импорта нет.
Приложение по-прежнему рассчитано на **один процесс/worker**: admission-блокировки и реестр ресурсов
живут в AppContext, а задания/команды сохраняются в SQLite.

### Отзыв сессий

Подпись `initData` подтверждает личность. Отдельный AccessService разрешает вход по базе.
Каждый запрос сверяет статус и `auth_version`; роль не берётся из cookie или frontend.
Версия увеличивается при блокировке, восстановлении и изменении роли; подпись, срок, Secure/HttpOnly/
SameSite, Origin и CSRF остаются обязательными. Старые cookie без версии требуют повторного входа.
При отзыве допуска React убирает кабинет и кэш, прекращает опрос и предлагает переоткрыть Mini App.

## HTTP API

Все маршруты под `/api/v1/admin`. Мутации требуют CSRF/Origin и `Idempotency-Key` (8…128 символов).
У остановки ответ 202 с `action_id`, текущим состоянием и списком целей. Повтор ключа с другим действием
возвращает 409. Принятые инициатор, операция и цели неизменяемы; меняются только ход и результаты исполнения.

| Маршрут | Доступ |
|---|---|
| GET overview, tasks, actions, actions/{id}, errors | ADMIN/ROOT |
| GET members, members/{id}, invitation | ROOT |
| POST members; PATCH members/{id}; POST members/{id}/block, restore | ROOT |
| POST tasks/{id}/stop; POST tasks/stop-all | ADMIN/ROOT, ROOT защищён |
| POST actions/{id}/retry-cleanup | По текущей роли и защите целей |

Пагинация `offset`/`limit`, 50 по умолчанию, максимум 100; `next_offset=null` завершает список.
Люди поддерживают `search`, `role`, `access_status`; задания — `status`, `user_id`.
Новые административные Telegram ID — строки, даты — UTC ISO; интерфейс отображает МСК.
Ошибки содержат `detail.code` и `detail.message`: 401 сессия, 403 доступ/роль, 404 отсутствие,
409 версия/защита/идемпотентность, 422 неверный ввод.
`GET /me` добавляет `role` и `admin_capabilities`, сохраняя личные данные только текущего пользователя.

## Диагностика и хранение

Обзор не обращается к ИИ за генерацией. Он показывает кешированный последний результат обращения
или проверки модели, время и устаревание через 15 минут. Polling означает живую задачу процесса,
а не гарантированную доступность сети Telegram. Следующий поиск берётся из задания `hh_auto_search`.
Обзор опрашивается каждые 15 секунд, задания/принятые остановки — каждые 3 секунды в видимой вкладке.
Люди и журнал обновляются после изменений, возвращения в приложение и вручную.

Ошибки записываются в контролируемых точках по фиксированным кодам. `server.log` не читается и
не возвращается в браузер. В административное хранилище не попадают произвольные traceback,
токены, заголовки, тексты документов, промпты, коды входа и прокси с паролем.
Технические задания и ошибки хранятся 30 дней после завершения; успешная административная история —
90 дней. Незавершённые команды, активные задачи и нужные им метаданные не очищаются. Ежедневная
очистка запускается scheduler в 03:20 МСК; пользовательская история откликов не затрагивается.

## Выпуск и откат

Для проверки новой сборки без замены работающего frontend:

```sh
cd web
npx tsc -b && npx vite build --outDir ../scratch/admin-recheck-dist
cd ..
LEADSCOUT_TEST_WEB_DIST="$PWD/scratch/admin-recheck-dist" .venv/bin/python -m pytest -q
```

Браузерные тесты используют отдельные SQLite-базы и указанный production-бандл.
Рабочие роли и данные не меняются; внешние действия hh.ru подменены.

1. Сохранить SQLite через backup API, `.env` с исходным Fernet-ключом и прежний frontend-бандл.
2. Проверить миграцию на копии, новый frontend, полный pytest и Ruff.
3. Завершить старый процесс, задать ROOT, запустить согласованные backend/frontend.
4. Проверить health, авторизацию обеих административных ролей, личный кабинет и HTTPS-туннель.
5. Владельцам переоткрыть Mini App. Реальный вход внутри Telegram на устройствах проверяется отдельно.

Для отката на код с поддержкой только v6 остановите v7-процесс, сохраните текущую v7-базу со всеми
новыми данными отдельно, восстановите соответствующую v6-копию и прежний бандл/код. Старый backend
отказывается работать с v7. Восстановление старой копии не переносит автоматически данные, появившиеся
после обновления; их перенос требует отдельного согласованного действия.

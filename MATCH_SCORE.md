# Match Score: управляемая оценка вакансий для каждого hh-аккаунта

## Кратко

Заменить бинарный фильтр `is_relevant` на отдельный Match Score 0–100 с прозрачными факторами, уверенностью в данных и тремя маршрутами: автоотклик, ручная проверка, пропуск.

Система запускается безопасно: первые 50 вакансий на каждом аккаунте только оцениваются и показываются в статистике. Текущая автоматика продолжает работать без изменений. После калибровки пользователь вручную включает новую маршрутизацию.

## Основные изменения

- Добавить отдельный профиль соответствия на каждый hh-аккаунт:
  - основные и смежные роли;
  - исключаемые роли и стоп-слова;
  - обязательные и желательные навыки;
  - существующие предпочтения: удалёнка, минимальная зарплата, ключевые слова;
  - редактируемые веса и пороги;
  - режим: `DRAFT`, `CALIBRATING`, `AWAITING_APPROVAL`, `ACTIVE`.

- Создавать AI-черновик профиля из выбранного резюме, но не включать его без подтверждения пользователя. Для существующих аккаунтов оставить текущую автоматику в legacy-режиме, пока профиль не создан и не подтверждён.

- Использовать базовые веса, сумма которых всегда равна 100:
  - роль и домен — 20;
  - обязательные навыки — 25;
  - уровень и опыт — 15;
  - стек и техническая глубина — 15;
  - задачи и контекст проекта — 10;
  - формат и условия работы — 10;
  - зарплата — 5.

- Выполнять жёсткие проверки до AI-оценки:
  - не удалёнка при активном фильтре удалённой работы;
  - известная зарплатная вилка целиком ниже минимума;
  - роль или стоп-слово из профиля;
  - подтверждённое несовместимое обязательное требование.
  
  Отсутствующие сведения не считаются несовпадением и не обнуляют вакансию.

- Добавить структурированную AI-оценку: баллы по каждому фактору, подтверждённые совпадения, отсутствующие обязательные навыки, стоп-причины и краткое безопасное объяснение. Сервер, а не модель, вычисляет итоговый Score по весам.

- Хранить отдельно `confidence`: долю весов, для которых есть конкретные данные и подтверждающее основание. Неизвестный фактор исключается из расчёта Score, но снижает confidence.

- В `ACTIVE`-режиме маршрутизировать вакансии:
  - `Score ≥ 85`, `confidence ≥ 80`, нет стоп-условий и неизвестных обязательных требований — автоотклик;
  - `Score 65–84`, либо высокий Score с недостаточной уверенностью — очередь проверки;
  - `Score < 65` или стоп-условие — пропуск с сохранённой причиной.

- Во время калибровки вычислять и сохранять Match Score для всех кандидатов, но продолжать текущую бинарную логику отклика без изменений. После 50 оценённых вакансий перевести профиль в `AWAITING_APPROVAL` и показать сводку; только пользователь включает новый режим.

- Создать долговечную очередь Match Review, отдельную от очереди анкет:
  - хранить ссылку, название, Score, confidence, факторы, причины, статус и версию профиля;
  - `Одобрить и отправить` создаёт единственную сериализованную задачу отклика для этого аккаунта;
  - перед отправкой заново проверяется сессия, дубликат и актуальность вакансии;
  - при ошибке повторная отправка не выполняется автоматически;
  - `Пропустить` сохраняет явную обратную связь и ничего не отправляет.

- Сохранять причины оценки в безопасном структурированном виде; не записывать в технические логи резюме целиком, исходный prompt, телефон, email или сырое содержимое страницы hh.ru.

## Интерфейс и API

- В настройках аккаунта добавить блок «Профиль соответствия»:
  - создание и подтверждение AI-черновика;
  - роли, исключения, обязательные/желательные навыки;
  - веса с валидацией суммы 100;
  - пороги Score;
  - индикатор режима и прогресса калибровки `N / 50`.

- На главной странице показывать текущий режим профиля, число оценённых вакансий и количество Match Review.

- На странице «Отклики» разделить проверку на две очереди: существующие анкеты hh.ru и вакансии Match Review. Карточка вакансии показывает Score, confidence, совпадения, пробелы, краткое объяснение и действия «Одобрить и отправить» / «Пропустить».

- Добавить защищённые API для:
  - чтения, создания черновика и подтверждения Match Profile;
  - обновления профиля и весов;
  - выдачи очереди Match Review;
  - одобрения и пропуска вакансии;
  - получения статистики калибровки и агрегированных причин отсевов.

- Добавить миграцию SQLite с таблицами профилей и оценок вакансий. Старые аккаунты, история откликов и текущие настройки не изменяются; новые таблицы заполняются только для новой логики.

## Проверки

- Модульные тесты расчёта весов, стоп-условий, неизвестных факторов, confidence и порогов `85 / 65`.
- Тесты AI-контракта: невалидные баллы, пустые доказательства и небезопасные причины отклоняются или заменяются безопасной ошибкой.
- Тесты калибровки: 50 оценок не меняют текущую автоматику; после 50 требуется явное подтверждение.
- Тесты маршрутов: автоотклик, очередь проверки, пропуск, одобрение, отмена, дубликаты, истёкшая сессия и недоступная вакансия.
- API-тесты изоляции по пользователю и аккаунту, прав доступа и атомарности одобрения.
- React-тесты профиля, прогресса калибровки, двух очередей и запрета двойного клика.
- Полный `pytest`, `ruff check`, production-сборка frontend, проверка миграции на копии рабочей SQLite-базы и ручной сценарий на тестовом аккаунте.

## Принятые решения

- Настройки и обучение обратной связью изолированы по каждому hh-аккаунту.
- На первом этапе отзывы пользователя сохраняются и отображаются в аналитике, но не меняют веса автоматически.
- Основной AI-провайдер не меняется.
- Текущая работа бота не останавливается при подготовке; выпуск потребует одного короткого планового перезапуска общего процесса.
